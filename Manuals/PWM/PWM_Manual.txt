MANUAL DE PWM MANAGER
=====================

1. FINALIDAD Y FUNCIONALIDAD
----------------------------
PwmManager es el registro central de las salidas PWM del proyecto. Su finalidad
es describir cada salida antes de tocar el hardware, asignarle un nombre y evitar
configuraciones incompatibles. El manager no genera la señal: conserva y valida
la configuración que después consume un objeto PwmOutput.

Cada registro almacena nombre, GPIO, slice, canal, frecuencia, cantidad de pasos,
valor wrap y si el slice debe ser exclusivo. En RP2040, dos GPIO pueden compartir
un slice PWM; ambos canales del mismo slice comparten frecuencia y wrap. Por eso
el manager rechaza canales repetidos, slices exclusivos o parámetros distintos en
un mismo slice.

2. CUIDADOS ANTES DE USARLO
---------------------------
* Cree un solo PwmManager con una vida útil mayor que todos sus PwmOutput. Estos
  guardan un puntero al manager y este no debe destruirse antes que ellos.
* Use nombres únicos, no vacíos y de hasta 15 caracteres útiles. El carácter 16
  se reserva para el terminador de la cadena.
* Use GPIO válidos para la placa. La implementación acepta números 0 a 29, pero
  eso no significa que todos estén expuestos o libres en cada modelo de Pico.
* Un nombre nuevo crea una salida. Un nombre existente solicita actualizar esa
  salida; compruebe siempre el retorno para no asumir que el cambio fue aceptado.
* Un PWM nuevo o actualizado no puede utilizar el GPIO reservado por otro PWM.
* frequencyHz debe ser mayor que cero. periodSteps debe estar entre 1 y 65536.
* GPIO que comparten slice solo pueden coexistir si ocupan canales diferentes,
  tienen igual frecuencia e igual periodSteps y ninguno exige exclusividad.
* Para un servo se recomienda un slice exclusivo, 50 Hz y suficientes pasos para
  representar con precisión pulsos de 500 a 2500 microsegundos.
* Compruebe siempre el código devuelto por registerPwmOutput() y llame a
  validateRegistrationStatus() antes de inicializar las salidas físicas.
* La clase admite como máximo 8 salidas y conserva hasta 16 intentos de registro.

3. INSTANCIACIÓN Y REGISTRO
---------------------------
Incluya las dos interfaces:

    #include "PwmManager.h"
    #include "PwmOutput.h"

Cree el registro y agregue las configuraciones:

    PwmManager pwmManager;

    int ledResult = pwmManager.registerPwmOutput(
        "LED_PWM", 15, 1000, 1000, false
    );
    int servoResult = pwmManager.registerPwmOutput(
        "SERVO", 16, 50, 20000, true
    );

El orden de parámetros es: nombre, GPIO, frecuencia en Hz, pasos del periodo y
exclusividad del slice. Un resultado igual a PwmManager::PWM_OK indica éxito.

4. ACTUALIZACIÓN AUTOMÁTICA POR NOMBRE
--------------------------------------
registerPwmOutput() funciona como registro o actualización. NAME es el
identificador estable: si no existe, se agrega una salida; si ya existe, el manager
intenta reemplazar los datos del mismo slot.

    int firstResult = pwmManager.registerPwmOutput(
        "PUMP", 6, 500, 2000, true
    );

    int updateResult = pwmManager.registerPwmOutput(
        "PUMP", 6, 750, 1000, true
    );

La segunda llamada encuentra PUMP y valida GPIO, frecuencia, periodSteps, slice,
canal y exclusividad contra todos los PWM salvo el propio PUMP. Si retorna PWM_OK,
sobrescribe el mismo slot y recalcula slice, canal y wrap. Si retorna un error, la
configuración anterior permanece intacta. Una actualización tampoco incrementa la
cantidad de salidas, incluso cuando el registro ya está lleno.

La búsqueda automática no permite cambiar NAME: para actualizar PUMP se debe usar
otra vez "PUMP". Un nombre diferente representa una salida nueva. Realice estas
actualizaciones antes de PwmOutput::init(); un PwmOutput ya inicializado conserva
la copia anterior y no reconfigura automáticamente el hardware.

updatePwmOutput() permanece disponible cuando se desea exigir que el nombre exista.
A diferencia de registerPwmOutput(), devuelve PWM_ERROR_NOT_FOUND en vez de crear
una salida cuando no encuentra el NAME indicado.

5. CONSTANTES Y CÓDIGOS DE RESULTADO
------------------------------------
MAX_PWM_OUTPUTS (8): máximo de salidas registradas correctamente.
PWM_NAME_MAX_LENGTH (16): tamaño total del búfer del nombre.
MAX_PWM_REGISTRATION_ATTEMPTS (16): intentos cuyo resultado puede almacenarse.

PWM_OK (0): operación correcta.
PWM_ERROR_INVALID_NAME (-1): nombre nulo o vacío.
PWM_ERROR_NOT_FOUND (-2): no existe una salida con el nombre solicitado.
PWM_ERROR_NOT_INITIALIZED (-3): objeto requerido todavía no inicializado.
PWM_ERROR_INVALID_PERIOD_STEPS (-4): frecuencia o pasos fuera del intervalo.
PWM_ERROR_REGISTRY_FULL (-5): se alcanzaron las 8 salidas.
PWM_ERROR_GPIO_INVALID (-6): GPIO fuera del intervalo 0..29.
PWM_ERROR_GPIO_USED (-7): el GPIO ya fue registrado.
PWM_ERROR_NAME_USED (-8): conflicto de nombre detectado por la validación interna.
PWM_ERROR_SLICE_CONFLICT (-9): exclusividad o temporización incompatible.
PWM_ERROR_CHANNEL_CONFLICT (-10): el canal del slice ya está ocupado.

6. MÉTODOS PÚBLICOS DE PwmManager
---------------------------------
PwmManager()
    Construye un registro vacío e inicializa sus contadores y arreglos.

bool isFull() const
    Devuelve true cuando ya existen 8 registros correctos.

bool nameAlreadyUsed(const char* name) const
    Indica si el nombre ya pertenece a una salida registrada.

bool gpioAlreadyUsed(uint gpioPin) const
    Indica si el GPIO ya está reservado por este manager.

int registerPwmOutput(const char* name, uint gpioPin,
                      uint32_t frequencyHz, uint32_t periodSteps,
                      bool requireExclusiveSlice)
    Busca primero una salida con el mismo name. Si no existe, valida y registra
    una salida nueva. Si existe, valida los datos nuevos ignorando solamente el
    slot que será reemplazado y lo actualiza sin aumentar la cantidad de registros.
    En ambos casos compara la configuración contra todos los demás PWM, calcula
    slice, canal y wrap (periodSteps - 1), imprime el resultado y devuelve PWM_OK o
    un código negativo. true en el último argumento impide compartir el slice con
    cualquier otra salida.

int updatePwmOutput(const char* name, uint gpioPin,
                    uint32_t frequencyHz, uint32_t periodSteps,
                    bool requireExclusiveSlice)
    Busca una salida existente por name y reemplaza sus datos asignados después de
    validarlos contra todos los demás registros. Durante la validación ignora solo
    el slot que será reemplazado, por lo que permite conservar su propio nombre y
    GPIO, pero sigue rechazando conflictos con cualquier otra salida. Recalcula
    slice, canal y wrap sin cambiar la cantidad de registros. Devuelve
    PWM_ERROR_NOT_FOUND si el nombre no existe. La actualización del registro no
    reconfigura automáticamente un PwmOutput que ya haya sido inicializado.

int updatePwmOutput(const char* name, uint gpioPin,
                    uint32_t frequencyHz, uint32_t periodSteps,
                    bool requireExclusiveSlice)
    Busca una salida existente por name y reemplaza sus datos asignados después de
    validarlos contra todos los demás registros. Durante la validación ignora solo
    el slot que será reemplazado, por lo que permite conservar su propio nombre y
    GPIO, pero sigue rechazando conflictos con cualquier otra salida. Recalcula
    slice, canal y wrap sin cambiar la cantidad de registros. Devuelve
    PWM_ERROR_NOT_FOUND si el nombre no existe. La actualización del registro no
    reconfigura automáticamente un PwmOutput que ya haya sido inicializado.

bool validateRegistrationStatus() const
    Imprime un resumen de todos los intentos guardados. Devuelve true solamente
    si ninguno falló. No sustituye la comprobación inmediata de cada retorno.

int getPwmConfigByName(const char* selectedName,
                       PwmOutputConfig& outputConfig) const
    Copia en outputConfig la configuración que coincide con el nombre. Lo usa
    PwmOutput::init(), aunque también puede emplearse para consultar el mapa.

void printPwmMap() const
    Imprime por consola todas las salidas aceptadas y sus recursos PWM.

7. ESTRUCTURA PwmOutputConfig
-----------------------------
name: identificador textual; gpioPin: GPIO físico; sliceNum: slice calculado;
channel: canal A o B; frequencyHz: frecuencia; periodSteps: resolución solicitada;
wrap: cuenta máxima del hardware; requireExclusiveSlice: política del slice;
used: indica que la entrada contiene un registro válido.

8. FLUJO INTERNO EXPLICADO
--------------------------
1) El constructor vacía salidas, resultados y contadores.
2) registerPwmOutput() busca primero NAME para decidir entre alta y actualización.
3) Si es una actualización, la validación ignora únicamente el slot encontrado.
4) Se comprueban capacidad, nombre, GPIO, frecuencia y pasos según la operación.
5) hardware_pwm convierte el GPIO a slice y canal.
6) El manager compara los datos contra todos los demás registros y slices.
7) Si son compatibles, asigna el slot, calcula wrap y guarda PWM_OK.
8) Si fallan, guarda el código y no modifica la configuración anterior.
9) PwmOutput solicita luego esos datos mediante getPwmConfigByName().
